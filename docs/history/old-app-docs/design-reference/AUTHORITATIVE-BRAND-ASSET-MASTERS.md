# Project Check — Authoritative Brand Asset Masters

**Status:** LOCKED / AUTHORITATIVE

**Applies to:** the whole Project Check project — website, application UI, reports, PDFs, customer workspace, marketing material, future design work and implementation.

## Governance principle

The approved Figma master files control Project Check visual brand assets. GitHub records their authoritative status and the implementation rules that follow from that status.

Code, screenshots, exports, local copies and historical assets are implementation copies or references only. They do **not** independently redefine the approved brand asset.

A master remains controlling until Stuart explicitly approves a replacement or amendment. A superseded master must be recorded as **SUPERSEDED**; it must not be silently overwritten, reinterpreted or replaced.

## 1. Logo Master — AUTHORITATIVE

The existing approved Project Check **Logo Master** in Figma is the authoritative reference for all Project Check logo usage across the whole project.

All website, application, report, PDF, title-block, workspace, marketing and future design implementations must use or faithfully reproduce the approved master logo.

Do not redesign, redraw, reinterpret, substitute, simplify, restyle or create a competing Project Check logo unless Stuart explicitly approves a new master.

Where an implementation requires a different size or file format, the visual proportions, geometry, colours, wordmark, underline and tagline treatment must remain faithful to the master.

## 2. Banner Master — AUTHORITATIVE

The existing approved Project Check **Banner Master** in Figma is the authoritative reference for all Project Check banner/header treatment across the whole project.

All implementations must follow the approved master for proportions, colours, spacing, alignment, hierarchy and visual treatment unless Stuart explicitly approves a superseding master.

Responsive implementation may adapt to available screen width, but it must preserve the approved design intent rather than independently redesigning the banner.

## 3. Icon Master — AUTHORITATIVE

The approved Project Check **Master Icon System** in Figma is the authoritative reference for all Project Check icons across the whole project.

Figma master: https://www.figma.com/design/nDnucbLDlaUHRdyPDFZ8Wy

Existing approved icons must be reused where applicable. Any genuinely new icon must follow the established master icon language, including line-art style, stroke treatment, proportions and Project Check navy/green palette.

Do not introduce emoji, unrelated icon libraries, materially different illustration styles or independently redrawn versions where an approved master icon already exists.

## Implementation hierarchy

For Project Check visual brand assets, the controlling order is:

1. Stuart's explicit approval / change decision.
2. Approved Figma master artwork.
3. This GitHub governance record.
4. Repository implementation assets and code.
5. Screenshots, exports and historical references.

If implementation code conflicts with an approved Figma master, the conflict must be reported and the code corrected to the master unless Stuart explicitly changes the master decision.

## Change control

Any proposed change to the Logo Master, Banner Master or Icon Master must be treated as a governed brand/design change, not a routine implementation adjustment.

A change is not authoritative merely because it has been committed to code. It becomes authoritative only when Stuart explicitly approves the revised master or explicitly supersedes the previous decision.

When a master is replaced:

- mark the previous master as **SUPERSEDED**;
- identify the replacement master;
- update this governance record if the controlling reference changes; and
- update implementation code/assets against the new master in a controlled change.
