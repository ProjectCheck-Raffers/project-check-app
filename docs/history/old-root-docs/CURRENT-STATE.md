# Project Check — Current State

**This is the most important document in the onboarding pack.** Every classification below was determined by inspecting the actual code (`app.js`, `evidence.js`, `geometry.js`, `drawing.js`) and the current protected specs (`MASTER-SPEC.md`, `EVIDENCE-INTELLIGENCE-SPEC.md`) as they stand at commit `d7b2dac` — not inferred from governance wording alone. Where a status was genuinely hard to pin down from inspection, it is classified cautiously and the reason is given.

**Legend:**
- **IMPLEMENTED** — real, working code in `app.js`/`evidence.js`/`geometry.js`/`drawing.js` today.
- **PARTIALLY IMPLEMENTED** — a genuine but narrower piece exists; the full concept described in governance is not built.
- **RECORDED FUTURE ARCHITECTURE** — governance/spec text exists describing intended future capability; **no code implements it.**
- **NOT AUTHORISED / DEFERRED** — explicitly out of scope for now, not merely unbuilt.
- **KNOWN TECHNICAL DEBT** — implemented, but with a known, accepted, unresolved defect.

## A note on how to read this table

A "RECORDED FUTURE ARCHITECTURE" row is not a criticism or a backlog item you should pick up unprompted — it means exactly what it says: the thinking is done and written down, the code is not written, and building it requires its own explicit, authorised task (see `DEVELOPER-RULES.md` rule 7 and rule 12). Do not infer urgency or priority from this table — that's a product decision, not something this document decides.
